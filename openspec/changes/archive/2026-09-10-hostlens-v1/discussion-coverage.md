# Discussion coverage audit

## Scope and ground truth

This audit compares the HostLens planning artifacts against the user-visible discussion through the request to create this repository. The latest accepted decision takes precedence over earlier proposals. The scope is documentation and architecture coverage, not implementation correctness or an operational security certification.

Reviewed sources include the proposal, all ten capability specifications, design, YAML examples, and implementation checklist. The conversation is the requirements source; external product documentation cannot establish what the user agreed to build.

**Result:** The audit found partial omissions in the first draft and added explicit coverage below. No remaining omission of an accepted v1 decision was identified in this audit. Deferred ideas and unresolved implementation details are recorded separately, rather than represented as completed decisions.

## Superseded proposals and deferred ideas

The discussion explored alternatives before selecting the architecture. Keeping every early proposal as a v1 requirement would introduce contradictions.

| Topic                                                                                            | Final disposition                                                                                                                                         |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Zabbix, Prometheus, Grafana, and a central monitoring database                                   | Early options, not selected dependencies of HostLens                                                                                                      |
| Local model inference                                                                            | Superseded by the user's external-provider preference                                                                                                     |
| SSH-only central coordinator                                                                     | Superseded by per-host MCP gateways; SSH tunneling remains a deployment option                                                                            |
| Separate diagnostic and remediation MCP connections                                              | Superseded by one gateway connection with separately privileged backends                                                                                  |
| Profiles containing only path lists and no includes                                              | Superseded by structured YAML profiles with includes and typed allow/deny rules                                                                           |
| Separate allow-profile and deny-profile lists                                                    | Superseded by profiles containing both sections plus direct main-file rules                                                                               |
| Always unprivileged diagnostic backend                                                           | Superseded by explicit standard and restricted installation modes                                                                                         |
| Exact distribution releases as compatibility gates                                               | Rejected; representative testing and interface detection selected                                                                                         |
| Standalone host notes, dependencies, incident history, and runbooks                              | Relevant to brainstorming, but no v1 storage/authoring contract agreed; retained as future enrichment                                                     |
| Ansible role and fleet gateway                                                                   | Possible later distribution and scaling tools; not required for v1                                                                                        |
| General secret redaction                                                                         | Discussed as additional protection, never agreed as a guarantee or substitute for access policy; selective extraction remains an implementation technique |
| mTLS, OAuth login, OAuth machine credentials, and remote stdio                                   | Authentication/transport alternatives discussed; bearer plus Streamable HTTP selected for v1                                                              |
| Application probes, backup/certificate checks, metric history, autonomous incident notifications | Earlier monitoring examples; current host checks and externally scheduled diagnostics define v1                                                           |
| Future remediation, macOS, Windows, and native packages                                          | Retained direction, explicitly excluded from v1 implementation                                                                                            |

## Open details, not missing decisions

The conversation did not select a GitHub owner or visibility, license, final Go module path, exact dependency versions, or release-signing mechanism. Numeric health thresholds, CPU sampling duration, transport limits beyond the discussed defaults, and supported file-log parsers remain implementation details to document and validate.

These are also recorded in [design retained future direction](design.md#retained-future-direction) and corresponding [tasks](tasks.md). No default or implementation evidence is invented to make the specification appear finished.

## Limits of this audit

OpenSpec structural validation checks artifact shape and scenario syntax; it does not prove coverage of a conversation. This mapping supplies traceability for that separate review. No runtime behavior, security containment, performance, or cross-platform portability has been tested because the implementation does not exist.

The strongest supported conclusion is that this audit found no remaining unrecorded accepted v1 decision. It is not a claim that every idea mentioned was selected for implementation, or that no later clarification will be necessary.

## Implementation follow-up (2026-09-10)

The original discussion audit above remains historical evidence of planning coverage. The selected module is `github.com/Monska85/hostlens`; runtime pins, safe path semantics, parser formats, defaults, and local archive verification are now recorded in the design and [operator instructions](../../../../docs/v1/OPERATIONS.md). [Validation evidence](../../../../docs/v1/VALIDATION.md) maps requirements to container tests and distinguishes native amd64 from emulated arm64 execution. The local implementation is reviewed and archived; publication remains deferred. The user explicitly requires container tests by default and approval before any strictly necessary VM provisioning, image download, or startup.
