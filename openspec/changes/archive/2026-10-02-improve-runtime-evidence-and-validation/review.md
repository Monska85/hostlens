# Review record

## Baseline

The cycle began at local commit `c426c3b`, one commit ahead of `origin/main`, with a clean worktree and 28,450 tracked Go lines including tests. The established disposable benchmark used Go 1.27.0 on Linux amd64 and five 200 ms samples. Median 5,000-image inventory was 2.32 ms, 2,919,313 B, and 266 allocations per call; 5,000-container inventory was 0.81 ms and 36 allocations. The 200-link process fixture measured 221 µs and the gateway request fixture 243 µs (disabled) or 239 µs (enabled). These are isolated fixtures, not production Docker latency.

## Implementation discoveries

- The existing live fixture test was opt-in, could address an arbitrary daemon, and decoded network results as volume payloads. The private nested-engine runner, socket guard, and typed network assertion corrected those gaps.
- The first private-engine run exposed Docker's unsigned maximum PID-limit sentinel. The observer now retains valid stats and omits the unavailable finite limit. A recording-engine regression and repeated live run passed.

## Complete review and fixes

1. **Performance and line balance:** Building only requested Docker reference maps initially regressed the image fixture to 2.37 ms and 268 allocations. Preallocating the image map and lazily creating volume/network maps improved the same fixture to a 1.97 ms median, 2,701,384 B, and 238 allocations. Container inventory stayed near 0.84 ms and process links near 222 µs. Gateway request medians moved to 277 µs (disabled) and 255 µs (enabled) across runs without a gateway request-path edit; no gateway speed claim is made. Kept the measured Docker variant.
2. **Trust boundaries:** Installation and release manifests now reject undeclared fields within their existing byte ceilings. Shared local identity lookup replaces duplicate parsers and bounds passwd/group reads. Gateway TLS restart hashing streams files instead of allocating their full contents. Tests cover malformed state, oversized identity files, and fingerprint behavior.
3. **Live authority and cleanup:** The acceptance test requires the private `/dind/docker.sock` path and runner marker; the runner rejects remote Docker endpoints, pins every outer command to the checked local socket even when `DOCKER_CONTEXT` is set, uses digest-pinned images, does not mount the outer socket, and fails on missing prerequisites. The checks container has a hard timeout and explicit cancellation cleanup. A live run passed; an injected remote endpoint failed before Docker contact.
4. **Contract and platform:** The PID-limit change omits the existing optional field without renaming JSON members. Make and Just call the same scripts directly. Race, vet, Linux amd64/arm64, and portable macOS/Windows package builds passed in the disposable checks container. Runtime support on macOS/Windows remains outside the product contract.
5. **Documentation and operator behavior:** AGENTS.md, release guidance, validation evidence, changelog, OpenSpec delta, and CI entry point were reconciled with the implemented behavior. Documentation formatting, shell/workflow lint, strict active and archived OpenSpec checks, and archive link resolution passed.
6. **Matrix evidence integrity:** The full local matrix printed 12/12, but inspection showed its two named arm64 systemd cases had run amd64 because the dispatcher dropped their declared architecture. The dispatcher now passes it to the systemd runner, which rejects a mismatched engine before container creation. The negative arm64-on-amd64 target reported `0/1` as intended. Native arm64 systemd validation remains a hosted-runner gate; prior local 12/12 output is not native arm64 evidence.
7. **Container supply chain:** The official Docker and BusyBox test images are pinned by manifest digest and prepared explicitly. A shared image configuration removes duplicated pins. `make prepare-live-docker`, the private engine test, and ShellCheck source-following lint passed. The privileged engine uses temporary storage, a private socket, no network, and a bounded checks process.
8. **Final integration:** The source diff, main-spec merge, task checklist, archive inputs, Make/Just parity, documentation links, and checked output were inspected together. No remaining implementation finding appeared; the exact candidate still needs the final matrix result before archival.

The source diff adds 23 net production Go lines relative to `c426c3b` (110 net relative to `origin/main`). New live acceptance tooling and regressions increase non-documentation lines. The change was kept for verified behavior and the measured 5,000-image allocation reduction; a net production line reduction was not achieved.

## Final validation

The final disposable `make test` passed the Go race suite, vet, Linux amd64/arm64 builds, portable macOS/Windows package builds, and all release, matrix, and developer utility tests. `make coverage` measured 86.8% internal statement coverage. Formatting, ShellCheck, Ruff, actionlint, GoReleaser configuration, and strict current/archived OpenSpec validation passed. The container-owned dependency scan reported no vulnerabilities at scan time.

The final GoReleaser snapshot archives for amd64 and arm64 passed checksum, member, contract-snapshot, and shipped-link checks. The exact-archive local matrix passed all ten runnable cases: four platforms (including emulated Debian arm64), two native amd64 systemd modes, and four application fixtures. Its two arm64 systemd cases explicitly failed before container creation on the amd64 engine, yielding `10/12` overall. Native arm64 systemd execution and the updated hosted CI workflow remain unverified for this local revision. The private live Docker runner passed using Docker 29.8.0 with `vfs` storage in a privileged nested container; the outer engine had no remaining test daemon afterward. None of these checks proves sustained production load, native macOS/Windows behavior, or a deployment.
