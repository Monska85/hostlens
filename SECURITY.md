# Security

Security fixes target the current release and development branch. The project has no long-term support branch.

Report suspected vulnerabilities privately to the repository owner. Use GitHub private vulnerability reporting if available. Do not put credentials, sensitive host output, or exploit details in public issues.

Include the affected commit, deployment mode, minimal reproduction, expected protection, and observed result. Use synthetic data and identify whether the issue requires local administrator access.

Review the [authorization and repair contracts](openspec/specs), [operator guidance](docs/current/OPERATIONS.md), and [validation limits](docs/current/VALIDATION.md) before deployment. Checksums detect corruption; obtain binaries and checksums through a trusted channel.
